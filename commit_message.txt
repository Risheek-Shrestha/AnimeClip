Fix signup/search/browse crashes, broken deploy pipeline, and missing age-gate enforcement

Five previously-broken core flows are fixed, the Docker/collectstatic
deploy pipeline now actually completes, age-rating/Kids Mode is
enforced for real instead of being cosmetic, and a structurally dead
notification path is replaced with a working one. 58 tests pass
(up from a suite that, once exercised end-to-end, failed on the
signup flow itself).

CRASH FIXES (each reproduced broken via the test client before fixing)

* Signup: render_to_string() referenced 'email_verify.txt', but the
  actual template is 'verify_email.txt'. Every signup threw
  TemplateDoesNotExist (500). Fixed the reference; updated
  test_signup_valid_age, which had been asserting the old
  pre-verification redirect-to-index behavior instead of the current
  "check your email" flow.

* Search (/search/): search_results.html had a stray, unmatched
  {% endif %} after the playlist-modal include, breaking template
  compilation. Every search query 500'd regardless of result count.
  Removed the stray tag; added SearchResultsViewTest covering
  zero-result, anime-result, and movie-result cases.

* Browse-all pages (/movies/recent/, /movies/popular/,
  /anime/recent/, /anime/popular/): all four included
  "_browse_filters.html", but the file on disk was named
  "browse_filters.html" (no underscore). All four 500'd. Renamed the
  file to match the underscore-prefixed partial convention already
  used by _playlist_modal.html; added BrowseAllPagesViewTest.

* collectstatic / Docker build: three missing static assets broke
  collectstatic outright (whitenoise.storage.MissingFileError),
  which is run during the Docker image build.
    - static/assets/fonts/ajax-loader.gif (Slick carousel) was
      referenced but never present — fetched the real file from the
      Slick project upstream.
    - font-awesome.css's @font-face rules referenced legacy
      .eot/.woff/.ttf/.svg files that were never shipped; only the
      modern .woff2 files exist. Trimmed each @font-face to just the
      woff2 source that's actually there.
    - style-3d.css referenced two custom background images
      (comingOut-bg.png, schedule-bg.png) that don't exist anywhere
      in the repo. Replaced both with CSS gradients built from the
      existing theme palette (--c-gold, --c-accent, --c-dark, etc.)
      rather than inventing placeholder binaries.
  collectstatic now completes cleanly end to end.

* Dockerfile/docker-compose: collectstatic ran as a RUN step at
  image-build time, but SECRET_KEY/DB credentials are only injected
  at container *runtime* via env_file/environment — so the build
  failed with "SECRET_KEY environment variable is not set" before
  it could even reach the missing-asset crash above. Moved
  collectstatic into the docker-compose startup command (ahead of
  migrate), matching how migrate was already handled.

SECURITY / FEATURE GAP — age-rating and Kids Mode were cosmetic

Verified by creating a 12-year-old account and an 18+ episode, then
hitting /streaming/<id>/ directly: got 200, full playback, no gate.
Age filtering only ever happened inside the recommendation engine's
candidate pool — never on the actual streaming, search, category,
or browse endpoints — and Movie had no age_rating field at all, so
movies could never be restricted under any circumstance.

* Added Movie.age_rating (mirrors Anime.age_rating; both now use a
  shared AGE_CHOICES constant). New migration 0023.
* Added ananimeclip/content_access.py as the single source of truth
  for "can this viewer see this content", combining account-level
  Profile.age and the active SubProfile.kids_mode.
* Enforced directly on streaming() and streaming_movie() — direct
  URL access to 18+ content by a restricted viewer now redirects to
  the homepage with a message, instead of rendering the player.
* Filtered search_results, live_search, category_page, movies,
  index, and all four browse-all views. Where these views share a
  cache across all users (category_page, movies, the homepage
  context, the four browse-all pages), filtering happens
  per-request *after* the cache read, not before the cache write —
  otherwise the first viewer's restriction level would leak onto
  every other viewer hitting that cache entry. live_search's cache
  key now includes the restriction level for the same reason.
* recommendations.py: Movie candidates are now age-filtered the same
  way Anime candidates are (previously unfiltered, per the code's
  own acknowledging comment).
* Added AgeGateTest (9 cases): minors blocked from streaming/search/
  category for 18+ titles, adults unaffected, and a Kids Mode
  sub-profile blocks 18+ content even on an adult account.

DEAD NOTIFICATION PATH — new_movie notifications could never fire

notify_new_movie fired on Movie post_save(created=True) and looked
for users with the movie in WatchLater/WatchHistory — impossible,
since nobody can have a watch-later/history row for a movie that
didn't exist yet at the moment of its own creation. The "created"
signal was structurally the wrong trigger no matter which table got
queried.

* Generalized Follow (previously anime-only) to support movies too,
  via nullable anime/movie FKs with a check constraint requiring
  exactly one. Migration 0024.
* Added a Follow button on the movie streaming page (previously
  movies had no follow/favourite mechanism at all) and a Movies
  section on the Favourites page. Reuses the existing generic
  follow-btn JS handler unchanged.
* Added toggle_follow_movie view + URL.
* Removed the broken Movie post_save signal. Added
  Movie.release_notified (migration 0025) and a new periodic
  management command, notify_movie_releases, that notifies a movie's
  followers once its release_date actually arrives — mirroring how
  warm_recommendations is already documented to run via cron/Celery
  beat. Idempotent (won't re-notify on subsequent runs).
* Added MovieFollowTest and NotifyMovieReleasesCommandTest.

SMALLER FIXES

* add_to_playlist returned {'status': 'added'} even when neither
  episode_id nor movie_id was supplied, silently doing nothing.
  Now returns 400 with an error status.
* animeclip.js: the README claimed watch-progress saves use
  fetch(..., {keepalive: true}) — the actual code had no such flag
  and no handler for tab-close mid-playback. Added keepalive: true
  and a pagehide/visibilitychange flush.
* Email verification links never expired despite the email itself
  promising "this link expires in 24 hours". Added
  Profile.verification_sent_at (migration 0026) and enforced the
  24-hour window in verify_email(). Added two tests covering the
  success and expired-link paths.
* staticfiles/ (collectstatic output, ~11,600 files — roughly two
  thirds of everything previously tracked in this repo) was
  committed to git. Added it to .gitignore and untracked it; it's
  regenerated at deploy time, not version-controlled.
* README: documented the existing-but-unmentioned Docker/Compose
  setup path, and the Cloudinary unsigned upload preset
  (anime_videos_unsigned) that the admin video-upload widget
  silently depends on but the setup instructions never mentioned.
* recommendation_service.py: replaced
  __import__('django.db.models', fromlist=['Q']).Q(...) with a
  normal top-level `from django.db.models import Count, Q` import.

TEST INFRASTRUCTURE

* AuthViewTest.setUp() now clears the cache, since the signup view's
  5/hour per-IP rate limit was silently accumulating across test
  methods sharing the same test-client IP and would intermittently
  fail any test suite with more than 5 signup-posting tests in the
  class.
* Fixed IndexRecommendationsTest.test_no_recommendations_without_history,
  which asserted a 'recommended_movies' context key on the homepage
  that the view intentionally doesn't set (movie recommendations
  live on the Movies page, per the view's own docstring) — a stale
  test left over from when that feature was split across two pages.
